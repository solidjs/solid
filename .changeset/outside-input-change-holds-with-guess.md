An input changed outside an optimistic guess's action no longer tears the screen (#4336). When a `createOptimistic` or `createOptimisticStore` guess made in a pending action (a post's `mine (sending)` over `sel() = 3`) is re-asked because a plain write changed its input (`setSel(1)`), the write is held with that action (D-34). The screen keeps `#3: dana | mine (sending)` until the action commits, then shows `#1: ...` with its answer as one frame, whether the reads share one render effect or are split across several. `isPending` is true while the new question is in flight or held, including through the action's own `refresh()`, and `latest()` answers the newest truth. A `refresh()` of the same question still keeps its own frame. For a store, the hold applies to a frame that still reads a guess: a keyed store's other keys (`comments[1]` while the guess is on `comments[3]`) wait only for their own answer. An input set through its own optimistic write in another action now shows in its own lane once its answer lands, without the other action's guess beside it. Also fixed: a held write read in the same flush before the action's first lane read no longer shows before the commit. If that input's action ends without writing the truth, the other action's guess comes back in the revert's frame (`#1: ` then `#3: dana | mine (sending)`) and lasts until its own action settles; the split-effect form waits with the input's lane instead of showing `#1:` beside the guess. A `<Loading on>` boundary whose fallback reads `latest()` no longer swaps to its fallback ahead of a held change: the swap lands with the change's frame (#4337).
