# Behavioral-Diff Harness — design sketch

_Drafted 2026-08-25. Status: P1 sketch from the agent-diagnostics plan; not started._

## Problem

Port equivalence needs a correctness gate that does not depend on the source
app's test suite (often thin) or human review (does not scale to agent
throughput). The claim to verify: under the same scripted interactions, the
port produces the same observable behavior as the original.

## Approach

Record the original, replay against the port, diff the observations. Three
recorded streams per scripted scenario, all JSONL with `formatVersion`:

1. **Interaction script** — the input. Ordered steps (`click selector`,
   `type selector text`, `waitFor predicate`), authored once per scenario,
   shared verbatim between both implementations. Steps are the alignment
   keys for all diffing.
2. **DOM observations** — per step: a normalized snapshot digest of the
   regions the scenario declares it cares about (`observe: ["#list", ".header"]`),
   not raw MutationObserver streams. Mutation streams differ wildly between
   frameworks (VDOM replaces nodes; Solid mutates in place) — the equivalence
   claim is about _settled DOM state per step_, not the mutation path.
3. **Network trace** — per step: requests issued (method, URL pattern, body
   digest) and responses consumed. On record this doubles as a fixture
   recorder; on replay responses are served from the recording so both
   implementations see identical data and timing skew is eliminated.

## Normalization (where all the difficulty lives)

- Strip framework-specific attributes/comments (hydration markers, scoped
  style hashes), autogenerated ids/classes; canonicalize whitespace.
- Timing: settle per step (queue drain + rAF + network idle from the replay
  server) before snapshotting; never diff mid-transition states.
- Declared exclusions per scenario for legitimately divergent regions
  (timestamps, animations), which must be justified in the scenario file —
  an exclusion is a reviewed artifact, not an escape hatch.

## Report

Per scenario: pass/fail per step, first divergent step with both normalized
snapshots and a tree diff, plus network divergences (missing/extra/changed
requests). Emitted as JSONL + human-readable summary. A port slice ships when
every scenario passes behavioral diff AND its diagnostics budget (the other
half of the acceptance gate).

## Open questions

- Snapshot digest granularity: full serialized subtree vs structural hash
  with on-demand expansion (leaning: store full normalized subtree, hash for
  quick compare).
- Where it lives: with the port project, not in `@solidjs/diagnostics` —
  it is framework-comparative tooling, not a Solid channel. Revisit if a
  second consumer appears.
- Whether the interaction script format should just be Playwright code with
  a step-marker helper instead of a bespoke DSL (leaning: yes — step markers
  around plain Playwright keep authoring friction near zero).
