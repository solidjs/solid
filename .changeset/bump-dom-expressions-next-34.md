Adopt @dom-expressions/runtime 0.50.0-next.34 (per-args boundary identity, single-flight frames, boundary retention). Server-component boundary identity is now the call's intrinsic (function, arguments) address end to end: `installServerComponents` drops the `capture` option (the context-capture keying is gone from the runtime), a repeat call for the same (function, args) resolves the identical component — refetches morph the showing boundary in place — while an args switch swaps to that call's own boundary, re-materialized from the frame host's retained state. The document bootstrap's address → id records (`_$SC.a`, plus the live `reg` hook) forward to the transport's `showing` seam so a post-load call for a call the page already shows finds its way back to the adopted boundary, and the handler reads the single-flight consumer and codec through the SHARED server-functions client instance (this package's frames entry bundles the transport privately). The frame now invokes slots and element-claim sweeps through `ownerScope` even mid-render, so the integration's scope preserves an ambient owner when one exists — in particular a reveal boundary's content render — and only substitutes the boundary's owner for ownerless stream microtasks. The rxcore shim exports `runInServerComponentScope` as `undefined` (the frame sink's guarded context-barrier seam; Solid opts out for now).
